# Freshness and acceptance contract for dashboard clients

The numbered rules originated in the 2026-09-22 web API audit (commit 83ecdac).
The old static app was removed on 2026-09-27. References below name maintained
symbols rather than line numbers in that removed app:

- [`link.js`](../src/link.js): transport acceptance, ordering, resync and lifecycle;
  symbols named inside `createLink` are its local functions.
- [`store.js`](../src/store.js): displayed ages, live/retained observation policy.
- [`settings.js`](../src/settings.js): automatic view selection.
- [`link.test.mjs`](../test/link.test.mjs): synthetic transport regressions.
- [`api_schema.py`](../../api_schema.py): documentation-only Python wire types.

Historical ignition fallback guidance is identified in rule 14; current v2
stream, summary and layout counterparts are identified in rules 11, 13 and 16.
No client or server behavior is changed by these source references.

## Rules a client MUST implement

Constants (`link.js` exports): `MAX_STATE_FALLBACK_AGE_MS=5000`, `MAX_STREAM_DELIVERY_AGE_MS=10000`, `MAX_HTTP_ROUND_TRIP_MS=2000`, `STREAM_STALL_RESYNC_MS=3000`, `FRESHNESS_TICK_MS=1000`, `RESYNC_RETRY_MS=2000`, `SUPPLEMENTAL_REFRESH_MS=60000`; `DRIVER_QUALITIES={verified, observed_alfa_scale}` (`store.js::DRIVER_QUALITIES`).

1. **Delivery metadata MUST be validated** before any use (`link.js::validateDelivery`): `instance_id` non-empty string, `sequence` safe integer ≥1, `generated_at_ms` safe integer ≥1, `generated_monotonic_ms` safe integer ≥0. A snapshot without it is rejected (`missing_delivery_metadata`).
2. **Baseline MUST come from HTTP, never from the stream.** Fetch `/v1/snapshot?fresh=<Date.now()>-<seq>` with `cache: "no-store"`; measure `roundTripMs` with `performance.now()` (`link.js::createLink.fetchBaseline`). Reject when `roundTripMs > 2000` (`http_response_delayed`) → display "Broker unavailable: …" and retry after 2000 ms while visible.
3. **HTTP delivery age = full round trip** (conservative upper bound, `link.js::createLink.acceptBaseline`). On acceptance store `serverMonotonicOffsetMs = clientMidpointMonotonicMs − generated_monotonic_ms` and `serverMonotonicUncertaintyMs = roundTripMs / 2` (`link.js::createLink.acceptBaseline`).
4. **Stream events are accepted only when**: stream accepting flag set and page not hidden (`stream_blocked`); `instance_id` equals the HTTP-established instance (`instance_changed` → resync); an offset and uncertainty exist (`http_resync_required` → resync); and `deliveryAgeMs = max(0, performance.now() − (generated_monotonic_ms + offset)) + uncertainty` is ≤ 10000 and would not expire anything (rule 6) (`queued_stream_event` → resync) (`link.js::evaluateStreamEvent`, `deliveryAgeForStream`).
5. **Ordering within an instance**: reject if `sequence ≤ accepted.sequence` or `generated_monotonic_ms < accepted.generated_monotonic_ms` (`out_of_order`). An instance change is accepted only from HTTP; the old instance is added to a retired set (≤8) and any later event from it is dropped (`retired_instance`) (`link.js::evaluateStreamEvent`, `createLink.acceptBaseline`, `createLink.retireInstance`).
6. **Would-expire test** (`link.js::metricWouldExpire`, `wouldExpire`): for every `metrics[*]` with `available && !stale`: if `age_ms` is not a finite non-negative number or the catalog has no `stale_after_seconds` → expires; else expires when `age_ms + deliveryAgeMs > stale_after_seconds*1000`. Additionally, if `status.vehicle_state.confidence === "verified"`: invalid age → expires; else expires when `age_ms + deliveryAgeMs > 5000`.
7. **Ageing on acceptance** (`store.js::applyDelivery`, `upsertMetric`, `upsertVehicle`): add `deliveryAgeMs` to every `metrics[*].age_ms`, `status.cached_metrics[*].age_ms`, and `vehicle_state.age_ms`; set `stale=true` when the new age exceeds `stale_after_seconds*1000`, or the age is invalid, or `stale_after` is missing/negative. Verified `vehicle_state` older than 5000 ms → `{state:"unknown", running:null, confidence:"stale", basis:"client_freshness_expired"}`; verified with invalid age → `basis:"client_freshness_invalid"`.
8. **Observation state for display** (`store.js::observationState`): `quality = metric.quality ?? catalog-derived quality`; `stale = metric.stale || (validAge && age_ms > stale_after*1000) || (available && !validAge)`; `driverQualified = quality ∈ DRIVER_QUALITIES`; `heroReady = available && !stale && driverQualified`. Only `heroReady` values may appear as primary driver-facing numbers; `candidate` never does.
9. **Never use wall-clock fields for freshness.** `generated_at_ms` and `observed_at` are display-only. Ages are advanced only with `performance.now()` deltas.
10. **Watchdog every 1000 ms** (`link.js::createLink.watchdog`): if no delivery was accepted within the last 1000 ms, advance all ages by the monotonic delta since the last cursor and re-render time-sensitive panels only (`store.js::tick`, `ageMs`). If a stream is open and nothing was accepted for >3000 ms → resync (`stream_stall`).
11. **Resync** (`link.js::createLink.resync`): close the EventSource, bump a generation counter, HTTP-fetch; only if accepted *and* the page is visible: fetch supplementals and open a new EventSource (`link.js::createLink.startStream`; the current `STREAM_PATH` is `/v2/stream`). Any HTTP callback whose generation/sequence is obsolete MUST NOT render (`link.js::createLink.fetchBaseline`). EventSource `error` → resync (`stream_error`), which also covers the server's 300 s forced close.
12. **Visibility/page lifecycle** (`link.js::createLink.onVisibilityChange`, `onPageShow`, `invalidate`; `store.js::invalidate`): on `visibilitychange` (either direction) and `pageshow`: stop the stream, mark every available metric `stale=true`, set `vehicle_state` to `{unknown, null, "stale", basis: client_page_hidden|client_page_visible|client_page_restored}`, reset the age cursor, re-render if visible, and resync when visible. Do not assume `performance.now()` advanced during Android/Chrome suspension; that is why the cache is invalidated unconditionally.
13. **Supplementals** (`link.js::createLink.fetchSummary`): the cached history, health, DTC and maintenance products are fetched together through `/v2/summary` with `?fresh=` cache-busters and `cache:"no-store"` after every successful resync and every 60 s while visible, throttled to ≥60 s between starts; failed ones render as `{available:false, reason:"cache_unavailable"}`. They are rendered only when they arrive, never on the 1 Hz path.
14. **Ignition positive-presence semantics**: `vehicle.ignition_on` is a presence gate (`metrics.py::IGNITION_ON`, `publisher_values=(True,)`): a received 0x2EF frame yields `true`; silence never yields `false`, it yields staleness (`stale_after 5 s`) → unknown. UI: show ON/OFF only when `heroReady` and `typeof value === "boolean"`; otherwise show "—" with a stale/unavailable status (`store.js::observationState` provides the live/held/unavailable classification). The historical static UI’s `status.vehicle_state` ignition fallback (no dedicated counterpart in the maintained dashboard; `store.js::upsertVehicle` owns vehicle-state freshness) may be used **only** when the ignition metric has no live cache entry (`!ignitionMetric?.available`), and only if `confidence === "verified"` and `0 ≤ age_ms ≤ 5000`; it derives ON from state ∈ {moving, running, ignition_on} and OFF from `asleep`.
15. **Last-recorded display policy** (`store.js::RETAIN_LAST_READING`; vehicle-data README, “Last-recorded display policy”): only `battery.voltage, vehicle.odometer, engine.oil_life_remaining, engine.coolant_temperature, engine.vvt_oil_temperature, transmission.oil_temperature, tire.pressure.{fl,fr,rl,rr}, radar.alignment.{elevation,azimuth}` may show a dated value when not live. `candidate` quality is retained only for `vehicle.odometer` and the two radar metrics (`store.js::RETAIN_CANDIDATE_ESTIMATES`). Validation (`store.js::validRetained`, `retainedSample`): candidates are the live metric (if `available`) and `metric.last_recorded`; each must have a finite numeric `value`, `unit === definition.unit`, parseable `observed_at` within `store.js::FUTURE_TOLERANCE_MS` of the current wall clock, within `minimum..maximum`, a `source` present in the catalog whose quality equals the sample's, and quality driver-qualified or candidate-allowed; choose the newest `observed_at`. Retained values never count as live, never feed alarms/limits, and are shown with their original timestamp and a section-level "NOT LIVE" badge. Everything else (speed, RPM, ignition, oil pressure, torque/power, generator duty, shaft speeds, raw DIDs) is fresh-only.
16. **Automatic layout** (`settings.js::autoView`): freshness uses finite `ageMs`, `0 ≤ ageMs ≤ MAX_AUTOMATIC_STATE_AGE_MS` (**5000**). Live RPM selects Drive; otherwise verified fresh state ∈ {moving, running, ignition_on} selects Drive, and fresh state ∈ {asleep, parked} selects Parked (any confidence, so inferred asleep qualifies). Otherwise keep the current valid view, defaulting to Drive. This is the current counterpart to the removed `profiles.js` automatic layout, not a safety gate. Settings remain browser-local (`settings.js::loadSettings`, `saveSettings`) and never touch the broker.
17. **Broker-side staleness is not sufficient**: the server's `stale` flag was computed at broker serialization; a client MUST recompute after adding delivery age and MUST keep recomputing on the watchdog.
18. **Compute budget (tablet)**: the stream delivers ~40 KB JSON once per second and the watchdog fires once per second. Parse once, diff against the last render, and touch the DOM only for changed text/attributes (`store.js::upsertMetric` and `sameSample` keep unchanged observations stable). Skip the watchdog render in any second where a stream event already rendered (rule 10 does this). Ignore `status.cached_metrics` and `interface.role_interfaces.inventory`. Do not re-render the catalog, DTC, history, or health sections on the 1 Hz path. Prefer `requestAnimationFrame`-coalesced writes, avoid layout-thrashing reads, and pause non-essential re-renders while a scroll is in progress (e.g. defer for ~150 ms after the last `scroll` event, or only update panels observed on-screen via `IntersectionObserver`). Keep the 1 s SSE interval: the vehicle-data README’s “Dashboard freshness timing” section shows the 3.524 s worst-phase delivery needs it to stay under the 5 s expiry.

## v2 additions

19. **Catalog hash.** `/v2/stream` events carry `catalog_hash` instead of the catalog. The client keeps
    the catalog from its last HTTP baseline and MUST resync over HTTP when the hash changes.
20. **Status-lite.** `/v2/stream` events carry a reduced `status`. Fields absent from status-lite are
    read from the last `/v2/summary.status_full` and MUST be treated as at most 60 s old.
